## Input·Target 전용 2조건 프로토타입 — 2026-11-01

- 새 진입 `/?prototype=1`은 전체 Input·전체 Target만 받는다. 과제별 자연어 설명 필드는 없고, 서버도 초기 요구사항·추가 문맥을 거부한다. 선택적 추가 입력 표 외의 필드가 임의 유입되지 않도록 계약을 분리했다.
- LLM의 코드와 의미 Step을 실제 실행에 대응시킨다. 코드·할당 단위를 무조건 Step으로 정하지 않으며, 여러 문장을 한 Step으로 묶을 수 있다. 초기 임시 ID는 서버의 안정 ID로 교체하고 실행 대응 검증을 유지한다. 빈 Step 응답은 실패 처리한다.
- 프로토타입 A/C는 동일 초기 run·코드·Step·중간 표를 재사용한다. Ex-situ는 외부 코드/설명과 일반 전후 표, In-situ는 코드 없는 동일 설명/실제 전후 표와 관찰 기반 변화/확인된 경로다. 값 변화는 Target 정오 판정이 아니다.
- 합성 확인용 표는 본실험 과제가 아니며 `research_phase=prototype-validation`, `selected_for_study=false`로 기록한다. 기존 팀원 배정·P0 자료·진행 로그는 유지한다.

- 실호출 당시 마지막 집계는 공통 추적이었다. 이후 `as_index=False` 선택 열 집계의 실제 DataFrame 반환 추적을 보완했다. 저장된 **동일 모델 코드**를 추가 API 호출 없이 재실행하여 두 Step 모두 상세 추적과 집계 기여 행을 확인했다. 원래 실호출 증거와 이후 재실행은 보고서에서 구분한다.
- 로컬 회귀 **47 passed**(기존 Starlette 의존성 경고 1개), Node **24 passed**(입력 UI·워크플로·축척 15, 실제 변화 계산 9), TypeScript/Vite 프로덕션 빌드 성공. 생성 응답 계약·동일 실행·수정 범위/후속 값과 경로 변경·실패 후 마지막 성공 보존·되돌리기/확정·참가자 평가 비노출·추적 및 기존 배정을 검사했다. 팀 서버 8001 재기동과 미인증 화면/새 API의 접속 제한도 확인했다. 브라우저 시각 검증은 이번 변경에서 하지 않았다.

## 최신: 긴 Workflow Focus + Context와 실제 입력→출력 변화 — 2026-10-30

- 전체 순서 막대, 현재 위치/코드 참조, 이전·다음/방향키/Home/End를 A/B2/C에 제공한다. A/C는 선택 표와 가까운 두 표를 최대 3개 크게 표시한다. A의 코드 탭도 같은 범위를 따르고 B2는 단일 선택 Step의 코드+표 구성을 유지한다. 코드·실행·Step ID는 탐색으로 변경하지 않는다.
- C의 긴 summary/인자 JSON과 반복 조건 문장을 줄이고 확인된 연산 제목/조건/계산 관계를 표시한다. 현재 Step 실제 입력→출력의 추가/삭제 열·dtype·확인된 변경 셀/행·상대 순서 변화를 표시한다. 같은 Step의 이전 실행 대비 비교와 구분한다. 제외 행은 개수+펼침으로 제공한다.
- 원본→출력 행 대응은 상세 추적의 행 보존 연산에만 적용한다. 집계·병합·일반 Python 등은 실제 크기/스키마와 대응 미표시를 보여주며, 집계 기여 행을 삭제 행으로 표시하거나 일반 Python 관찰 ID를 계보로 사용하지 않는다. Target과 이전 실행은 새 변화 계산의 입력이 아니다.
