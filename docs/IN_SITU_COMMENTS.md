# In-situ 댓글 수정

C 조건은 워크플로의 Step 제목, 행 번호, 열 이름 또는 셀을 선택하면 근처에 작은 수정 버튼을 표시한다. 이 버튼을 누를 때 자연어 댓글 입력창을 연다. 단일 셀 클릭은 확인된 관련 출처를 표 안에서 강조한다. 별도 데이터 경로 섹션은 제거했다. A와 B2는 기존 하단 자연어 수정 패널을 사용한다. 모든 조건의 수정 범위와 실행기는 같다.

## 동작과 범위

- 워크플로의 단계 결과, 실제로 관찰된 제외 행, 원본 입력 표에서 Step/행/열/셀을 선택한다. 같은 표 안에서 셀을 드래그하면 사각형 범위를, 행 번호나 열 이름을 드래그하면 연속된 여러 행 또는 열을 선택한다. 여러 Step이나 일반 결과 표와 제외 행 표를 가로지르는 범위 선택, 서로 떨어진 영역의 동시 선택은 지원하지 않는다. 범위 강조는 수정 맥락이며 여러 셀의 상세 계보를 새로 추정하는 기능은 아니다. Input/Target 미리보기와 단계의 입력 펼침 표는 읽기 전용이다.
- 선택한 Step·행 ID·열·값과 기준 실행 버전을 댓글에 표시한다. 행·열은 해당 결과 안의 선택 강조이며, 확인하지 못한 셀 계보를 새로 추정하지 않는다. 확인된 셀 출처는 표 안에서 강조한다.
- 원본 입력 선택은 전체 파이프라인 요청으로 처리한다. 나머지는 선택 Step/전체 파이프라인 범위를 고를 수 있다. 선택은 수정 의도를 전달하는 맥락이며, 입력 표의 값을 직접 편집하거나 그 셀만 강제로 바꾸는 기능이 아니다.
- 같은 범위 정책을 사용하므로 선택 Step 밖의 코드 변경은 거절한다. 전체 재실행으로 후속 결과·설명·확인 가능한 경로를 갱신한다. 실행 완료를 Target 정답으로 표시하지 않는다.
- 서버가 현재 실행에서 Step과 연산의 소속, 행·열 존재, 제외 행 여부를 검증한다. 실제 선택 데이터는 보존된 관찰 표에서 구성한다. 클라이언트가 임의로 넣은 값은 선택 데이터로 사용하지 않는다. 기준 실행이 달라지면 기존 버전 검사로 거절한다.
- 요청 중에는 선택과 중복 전송을 막는다. 실패 시 댓글 초안과 마지막 성공 실행을 유지하고 실패 메시지를 표시한다. 성공 시 요청 문장과 새 버전의 재실행 완료를 보여준다. UI는 LLM이 새로 쓴 답변 문장을 만들어 보여주지 않는다.
- Step 옆 댓글 아이콘으로 같은 실행 이력의 최근 수정 요청 5개를 다시 볼 수 있다. 성공한 요청은 run.review_comment에 저장한다. 되돌리기 시 현재 실행의 부모 경로에 속한 이력만 표시한다. 미전송 초안은 같은 브라우저 화면의 선택·버전별 메모리에 유지되며 새로고침하면 사라진다.
- Escape로 닫고 Ctrl/Command+Enter로 전송한다. 입력창은 표의 overflow 영역 밖에 표시하고 화면/워크플로 스크롤에 맞춰 위치를 갱신한다. 작은 화면에서는 화면 안에 들어오도록 배치한다.

## 연구 비교 시 유의점

이번 C는 정보 표현 외에 **수정 입력 위치, 선택 단위, 모델에 전달하는 선택 맥락, 해당 Step의 수정 이력 접근**도 함께 달라진다. 따라서 A/B2 대 C를 전체 검수·수정 인터페이스의 비교로 해석할 수 있지만, 차이를 정보 배치 위치 하나의 효과로 분리해 주장할 수는 없다.

위치 자체를 분리하려면 후속 조건에서 Ex-situ에도 같은 행/열/셀 선택과 같은 수정 이력을 제공하고 입력창 위치만 달리하는 통제가 필요하다. 현재 구현은 먼저 탐색적 파일럿에서 전체 상호작용의 사용성을 검토하는 범위다. 모델·자연어 요청·Step 구조·초기 코드·실행 버전·수정 범위는 조건 간 동일하게 관리한다.

작은 수정 버튼과 범위 선택을 사용하는 현재 인터페이스는 selection-action-v2로 기록한다. 행/열 배열은 서버의 해당 관찰 표에서 확인하고 실제 선택 데이터를 구성한다. 기존 anchored-comment-v1 기록은 유지한다. 기존 조건 ID A/B2/C와 과거 로그는 유지한다. 새 요청에는 interaction=selection-action-v2, review_target_selected/review_comment_opened 및 column_selected 이벤트를 기록하고 review_started에도 revision_interface를 넣는다. 과거 C 요청과 새 댓글 요청을 분석할 때 이 인터페이스 표기를 구분한다.

## 검증

선택 맥락·제외 행·원본 선택·다른 Step의 연산 선택 거절·버전 충돌·참가자 평가 비노출·후속 표/경로 갱신·되돌리기 검증을 추가했다. 모델 대역을 사용하는 테스트와 실제 모델 요청의 결과는 별도로 기록한다.

2026-10-30 후속 변경: 작은 수정 버튼과 드래그 선택은 사용자 요청에 따라 추가 테스트·브라우저 검증·실제 모델 호출을 수행하지 않았다. 앞선 검증 기록을 이 후속 변경의 검증 결과로 인용하지 않는다.
