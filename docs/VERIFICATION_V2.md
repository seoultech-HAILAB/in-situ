# v2 과제 후보의 WoZ 연결 상태

2026-11-02 기준. 최신 자료는 `output/verification_task_selection_v2_20261102`다. 이전 선정 폴더는 변경하지 않았다.

## 개발자용 초기 오류 해설

**개발자 옵션 → 과제 관리 → 각 과제의 ‘초기 오류 해설’**을 펼치면 등록된 초기 오류 Step, 해당 Step의 전체 코드 줄 범위, 잘못된 처리, 실제 데이터 영향, 올바른 수정과 참조 코드 차이를 확인할 수 있다. 현재 활성 12개 후보를 설명하며 M4 A/B는 오류 없는 정상 대조로 표시한다. 오류 위치 미등록 과제는 정상으로 간주하지 않는다.

오류 해설은 고정된 초기 코드 기준이며 수정 후 현재 실행의 판정이 아니다. 후속 표에 전파된 차이는 추가 오류 Step과 구분한다. 다중 오류의 단독 수정·전체 수정 기록도 저장된 검증 결과에서 표시한다. 잘못된 의미 Step 수를 오류 개수로 세므로 한 Step 안에 여러 잘못된 처리가 있을 수 있다.

해설은 연구자용 후보 목록 응답과 개발자 화면에만 포함한다. 참가자용 과제 목록·Input/Target 응답은 기존 허용 필드를 유지하며, 참가자 계정의 후보 API 접근은 계속 차단한다. 원본 후보 파일·코드·평가 키·공개 상태·배정은 변경하지 않는다. 글로 읽을 자료는 `output/task_error_guides_20261102/초기오류해설.txt`다.

## 원본 기반 Hard 교체 후 현재 상태

현재 일반 `VERIFY2-M` A/B 8개와 `VERIFY3-H1/H2` A/B 4개가 활성 목록이다. 합성 `VERIFY2-H` 네 개는 별도 보관했다. 새 H1은 원본 주문 총액 코드의 4 Step, H2는 원본 창고 품목 코드의 3 Step이며 Step을 늘리지 않았다. 원본 2건과 도메인 Variant 2개로 구성되고 실제 원본 생성에는 과제 설명이 포함됐다. 현재 참가자 WoZ는 계속 Input·Target만 제공한다. 자세한 단독/전체 수정 증거는 `output/natural_hard_audit_20261102/결과요약.txt`, `manifest.json`, `app_verification.json`에 있다. 아래 v2 Hard 8/9 Step 검증은 교체 전 이력이다.

v2 importer는 기본적으로 교체된 합성 Hard를 다시 추가하지 않는다. 과거 후보를 의도적으로 복원하려면 별도 `--include-superseded` 옵션을 사용한다. 원본 기반 후보의 비공개 등록 및 앱 경로 검증은 `output/natural_hard_audit_20261102/register_and_verify.py`로 재현한다.

## 과제 목록 정리 후 현재 상태

사용자 요청으로 기존 과제 24개와 validation 메타데이터 1개를 `.local/pilot/archived-candidates/v2-only-eec80581d75c407c8fc0d3abd70f6c34`에 복구 가능하게 옮겼다. 활성 후보 목록에는 최신 v2 12개만 남았다. 새 후보의 비공개 상태와 기존 계정·세션·피드백은 유지한다. 이전 과제의 신규 수행 배정은 목록에서 제외하며, 아직 새 후보를 참가자에게 배정하지 않아 참가자 화면에는 배정 대기 상태가 표시된다. 아래 ‘기존 과제 유지’는 정리 전 통합 시점의 기록이다.

## 연구자 사용

1. `http://127.0.0.1:8001/?research=1`에서 연구자 계정으로 접속한다.
2. **새 Input·Target**의 과제 선택에서 `VERIFY2-` 후보를 선택한다. 또는 **개발자 옵션 → 과제 관리**에서 `VERIFY2`를 검색해 **입력부터 체험**한다.
3. 원본 Input·Target을 확인하거나 같은 표의 CSV를 업로드하고 **변환 시작**을 누른다. 추가 입력도 저장된 과제의 표를 사용한다.
4. 저장된 초기 코드·긴 의미 Step을 실제 실행한다. 조건 전환은 같은 실행을 재사용한다. 자연어 수정은 기존 모델 경로로 요청한다.
5. **초기 파이프라인 검수 기록**에서 초기 Step을 복수 선택하거나 오류 없음/판단 어려움을 기록한다. 이 기록은 수정 요청·최종 확정과 별개다.
6. 연구자 **세션 내보내기**에 원본 Step 대응, 자기 보고, 연구자 판정, 버전별 코드·실행·수정·실패·되돌리기·확정 로그가 포함된다.

## 등록과 출처

일반 4 Pair 8개는 각 4 Step, Hard 2 Pair 4개는 각 8 또는 9 Step이다. A/B는 도메인 Variant이며 Ex/In 조건명이 아니다. 새로 등록한 12개는 모두 `participant_enabled=false`, `selected_for_study=false`다. 기존 공개 과제·배정·계정·로그는 변경하지 않았다.

일반은 `adapted_luna_regeneration`, Hard는 `researcher_composite_of_observed_luna_errors`로 원래 provenance를 보존한다. Hard를 단일 Luna 실행에서 자연 발생한 두 오류 사례로 보고하지 않는다. 정상 대조 과제도 포함되며 모든 과제를 실패 사례라고 표기하지 않는다.

`python scripts/import_verification_v2.py`는 manifest 해시와 후보를 확인해 비공개 등록한다. 동일 후보는 재등록하지 않고, 같은 ID 내용이 다르면 덮어쓰지 않고 중단한다. 등록 보고서는 `.local/pilot/verification-v2-import.json`이다. 초기 실행에는 표·초기 코드·Step·sources 개별 해시와 전체 스냅샷 해시를 저장한다.

기본 WoZ 화면은 과제별 자연어 변환 요구사항을 표시하거나 모델에 주입하지 않는다. 후보의 description/participant_description은 연구자 자료로 보존한다. 초기 코드·Step 생성 호출은 없고 Step 설명 API는 기존 캐시/모델 경로를 유지한다.

## 복수 오류 응답과 비공개 판정

첫 실행의 Step ID·원래 순서·라벨을 `review_baseline`에 고정한다. 코드 수정이나 Step 삽입으로 현재 순서가 달라져도 초기 응답 기준은 바뀌지 않는다. 응답에는 초기 실행 ID, 현재 실행 ID·코드 버전, 조건, 선택한 Step ID 집합, 제출 시각을 기록한다.

연구자 판정은 Step 집합의 완전 일치와 누락·추가 선택을 저장한다. 판단 어려움은 채점하지 않는다. 정상 과제의 빈 정답 집합도 지원한다. 현재 출력과 Target의 일치는 별도로 저장하며, 오류 하나 발견·수정만으로 전체 성공이라고 집계하지 않는다.

참가자 응답과 세션 표시에는 정답 Step 집합·오류 개수·판정·참조 코드·원본 출처를 보내지 않는다. `task_provenance`와 `judgment_evaluations`는 참가자 투영에서 제거하며 응답 저장 API는 저장 확인과 참가자 자기 응답만 반환한다. 수정 성공 여부와 Target 정답 여부도 분리한다.

## 확인한 범위와 한계

- 현재 앱 경로에서 후보 초기 실행 12회와 Hard 단독/전체 수정 12회, 총 24회가 기대 결과를 충족했다. 정상 초기 2개만 Target과 일치했다. Hard는 각 오류 하나만 수정하면 불일치하고 두 오류 수정 시 일치했다.
- 위 수정 검증은 정해진 참조 패치를 반환하는 테스트 대역이다. 실제 자연어 모델 수정 검증이 아니며 새 모델 호출은 0회다. 임시 세션을 사용해 기존 사용 로그에 섞이지 않는다.
- `.local/woz-v2-validation/report.json`은 실행·조건 재사용·다중 Step 응답 결과다. 검증 스크립트는 `scripts/verify_woz_v2.py`다.
- Python 회귀 11개, Node 렌더링 6개, TypeScript/Vite 빌드를 통과했다. 참가자 인증에서 비공개 과제의 목록·표·실행 접근 차단도 확인했다.
- 실제 8/9 Step 실행 자료로 모든 Step의 탐색 항목과 선택 상태, Ex의 전체 코드 보존, In의 전후 표 구성, 복수 Step 체크박스를 렌더링 검증했다. 실제 브라우저 화면·1366×768 가독성·사람 수행 시간은 검증하지 않았다.
- Hard는 모두 common 추적이다. 실제 전후 표·열 구조/타입·크기는 제공하지만 개별 셀 대응·삭제 행·그룹 기여·상세 계보를 추정하지 않는다. 현재 표현이 연구 가설에 충분한지는 사람 Pilot에서 확인해야 한다.
- `pilot_blocks.json`은 배정 검토 자료로 유지했다. 새 배정을 활성화하거나 참가자 공개하지 않았다. 같은 Pair A/B의 중복 노출과 Hard/원천 일반 과제의 중복 노출을 피한 후 별도 참가자 블록으로 검토해야 한다.
