# 테이블부터 시작하는 고정 코드 실험

## 참가자 흐름

P01·P02·P03에는 [고정 과제·조건 배정](PILOT_ASSIGNMENT.md)을 적용했다. 아래 자유 과제 선택은 연구자/기존 일반 경로에 해당하며, 개인 파일럿 계정은 배정된 과제만 순서대로 시작한다.

과제 선택 → 원본 Input 불러오기 또는 동일 Input 업로드 → 변환 시작 → 준비 로딩 → 저장된 초기 코드 실제 실행 결과 검수 → 자연어 수정·전체 재실행.

Target은 과제 시작 전과 A/B/C 검수 화면 모두에서 Input과 함께 참가자에게 제공한다. 기존 세션도 새로고침하면 Target을 다시 표시한다. 자동 정오 판정·오류 해설·원본 P0 출처·reference_code는 참가자 응답에서 계속 제외한다. 기존 일반 생성 세션의 Input+Target 방식은 연구자용 직접 입력 경로로 유지한다.

입력 확인 화면은 과제 CSV를 직접 불러오고 다운로드·업로드를 제공한다. 서버가 업로드를 파싱해 원본의 열·행 순서·값·dtype과 같은지 검사하며, 실제 실행에는 등록된 원본 CSV를 사용한다. 추가 입력이 있으면 함께 보여주고 고정된 원본을 실행에 제공한다. 서로 다른 Input으로 선정 오류가 달라지는 것을 막는다.

## 로딩과 실제 실행의 구분

- 화면에는 ‘변환 코드를 준비하고 있어요’와 ‘검수 화면을 준비하고 있어요’를 표시한다. 초기 준비 화면은 최소 약 1.2초 유지하고, 실제 실행이 더 오래 걸리면 끝날 때까지 표시한다.
- 이 경로에서 새 초기 코드를 모델에 생성 요청하지 않는다. 저장된 initial_code와 Step 정보를 기존 격리 실행기에 전달해 중간 표와 최종 결과를 수집한다. Target은 worker에 전달하지 않는다.
- 저장 Output/중간 표를 미리 만들어 둘 필요가 없다. 연구자 notes나 별도 원실험 기록에 기존 Output을 재현 기준으로 보관할 수 있다.
- 연구 로그에는 source=stored_code, model_called=false, 코드·Step·입력·Target·추가 입력의 snapshot SHA-256, 실제 실행 시간, UI 준비 화면 설정을 기록한다. 로딩을 실제 모델 호출/생성 시간으로 집계하지 않는다. 준비 이후 review_started부터 검수 시간을 계산한다.
- 자연어 수정은 기존 실제 LLM 수정 경로를 사용한다. API 키가 없어도 고정 초기 코드는 실행할 수 있지만 자연어 API 수정에는 키가 필요하다. 초기 코드를 재생성하는 요청은 거절한다.
- 생성 seed/원실험 runner를 실행 의존성으로 추가하지 않는다. seed가 있으면 provenance 등 연구 기록으로만 보관한다.

## 개발자 옵션

헤더의 **개발자 옵션**에서 접근한다. 팀 모드에서는 연구자 계정에만 버튼과 API 권한을 제공한다. 로컬은 기존 연구자 통제 환경이며 URL/헤더 자체를 인증 수단으로 사용하지 않는다.

상단 과제 관리 카드에서 ID·이름·요구사항·Step 수·저장 코드 출처·추적 기록·공개 여부를 볼 수 있다. 검색/새로고침/JSON 등록, 입력부터 체험, 초기 코드 바로 실행, 선택적 연구자 참조 실행을 제공한다. 참조 코드 실행은 별도 연구자 세션이며 참가자 수정 성공으로 집계하지 않는다. 조건·등록 코드·재현·진단은 접힌 고급 옵션에 묶었다.

새 과제 등록 순서:

1. ‘합성 예제 템플릿 받기’로 JSON 형식을 확인한다. 템플릿은 mock이며 실제 Luna 산출물이 아니다.
2. id, title, description, input_csv, target_csv, initial_code, steps를 준비한다. reference_code·오류 해설·seed는 선택 사항이다. sources는 추가 Input CSV의 이름→내용 사전이다.
3. 실제 P0 산출물은 provenance에 출처를 명시한다. 출처가 없으면 저장 코드/출처 미기록으로 취급하며 실제 Luna 결과로 표시하지 않는다.
4. ‘과제 JSON 추가’로 등록한다. 같은 ID를 덮어쓰지 않는다. 등록 시 형식·CSV·Step/코드 대응을 검사하지만 실행 성공이나 연구 적합성을 자동 보증하지 않는다.
5. ‘입력부터 체험’으로 연구자 전용 후보를 시작할 수 있다. 초기 실험과 동일하게 저장 코드를 실행하며 초기 LLM 호출이 없다.
6. 실제 실험에 사용할 때만 ‘참가자 과제 목록에 공개’를 켠다. 기존 후보도 기본 비공개이며 자동으로 게시하지 않는다. 비활성 과제는 공개할 수 없다.

서버 파일로 직접 추가할 때는 TRACE_TASK_DIR(기본 .local/pilot/candidates/)에 ID.json을 넣는다. participant_enabled=true와 enabled=true인 과제만 참가자 목록에 표시한다. participant_title/participant_description으로 연구자용 명칭과 분리할 수 있다. 참가자 명칭/설명에는 오류 위치나 해설을 넣지 않는다.

## CSV 후보 16개와 팀 파일럿

`output/task_review_500/TRACE_task_candidates_multiple_errors_v3.csv`의 후보 16개를 원래 CSV 순서에 따라 **과제 01~16 / R500-001~016**으로 등록했다. 이 후보들은 팀원의 선택·체험 요청에 따라 공개했다. 새 JSON 수동 등록의 기본 비공개 정책은 유지한다. 번호는 별도 registry로 보존하며 CSV 정렬 변경으로 바꾸지 않는다. 원본 CSV는 수정하지 않고, 번호·서버 ID·실제 단계 수를 추가한 `output/task_review_500/TRACE_task_server_numbers_v3.csv`를 만들었다.

등록 명령은 `scripts/import_review_candidates.py --csv output/task_review_500/TRACE_task_candidates_multiple_errors_v3.csv --inventory .local/task_selection_500/inventory.json --out .local/pilot/candidates --state .local/task_selection_500/server-registration`이다. 원본 pickle/실행 기록이 필요한 로컬 가져오기 도구이며 서버 실행 자체에는 필요하지 않다. 원본 함수의 곧은 실행문과 입력 참조만 관찰 가능한 코드로 옮기며, 실행 의미·조건·상수는 고치지 않는다. 옮길 수 없는 함수는 하나의 관찰 블록으로 남긴다. 원래 코드와 관찰용 코드의 출력을 보관된 P0 출력과 비교한 뒤 등록하며 새 모델 호출은 없다. 16개 모두 원본 출력을 재현했다.

실제 관찰 단계 수는 번호 순으로 9, 8, 5, 7, 11, 5, 1, 3, 1, 1, 3, 2, 1, 1, 4, 1이다. CSV의 Step 계획은 미계측 제안이며, 빠진 연산을 실행에 추가하거나 존재하지 않는 중간 표를 만들지 않았다. 상세 어댑터가 확인하지 못한 연산은 공통 추적의 실제 전후 표·크기·스키마를 제공하며 셀 계보를 추정하지 않는다. 원본 영어 질문을 공개 과제 설명으로 사용했고, CSV의 설명 보완 메모는 오류 해설을 포함하므로 연구자 전용에 남겼다. 정식 실험 전에 연구자가 과제 설명의 명확성과 시각화 범위를 검토해야 한다.

과제 번호는 선택·입력·검수 화면과 개발자 카드에 표시한다. 개발자 옵션은 번호·원본 ID로 검색하고 식별 정보를 복사할 수 있다. 오류 해설과 미계측 Step 제안은 접힌 연구자 검수 기록에만 표시한다. 첫 체험 전에는 열지 않는다. 연구자 입력 화면에는 다음 시작 세션의 A/B/C 선택을 제공하며, 이전 검수 세션의 조건을 바꾸지 않는다.

세 팀원이 각자 조건을 고정하면 기능 문제는 찾을 수 있지만 개인차와 조건 차이를 분리할 수 없다. A/B 선택용으로는 공통 세 과제에 대해 팀원 1=A/B/C, 팀원 2=B/C/A, 팀원 3=C/A/B를 배정해 각자가 서로 다른 과제를 모든 조건에서 한 번씩 경험하게 한다. 현재 나머지 11개(05·12 제외)는 C로 3·4·4개씩 분담해 후보를 점검할 수 있다. 피드백에는 과제 번호·조건·막힌 단계·수정 요청·표현 문제·실험 사용 가능 여부를 기록한다. 이 파일럿의 시간/성공률을 조건 우열의 통계적 근거로 사용하지 않는다.

## API와 제한

- 참가자: GET /api/study-tasks, GET /api/study-tasks/{id}/input, POST /api/study-tasks/{id}/start.
- 연구자: 기존 /api/task-candidates 경로 아래 등록·공개·비공개 입력 체험/시작을 추가했다. 팀 참가자의 이 경로 접근은 기존 권한 검사로 차단한다.
- 세션에는 과제 정보와 초기 파일의 fingerprint를 저장한다. 한 번 시작된 세션은 원본 입력과 코드/실행 이력을 보존한다. 과제 목록 파일을 나중에 바꿔도 기존 세션에 덮어쓰지 않는다.
- 새 준비 흐름과 과제 관리 UI는 구현했고 TypeScript/Vite 빌드를 확인했다. 사용자 선호에 따라 브라우저/실제 모델 호출/로컬 회귀 검증은 추가하지 않았다.
- 정식 참가자별 과제 배정·조건 무작위화·1회 시작 제한·재접속 소유권은 추가하지 않았다. 파일럿은 공개 목록에서 직접 선택하는 방식이다. 연구자용 ‘참조 코드’ 실행과 이전 일반 세션 링크는 새 참가자 Task 시작과 구분해 사용한다.
- 백엔드 API가 추가되어 실행 중인 서버는 재시작해야 한다. 파일·키·원본 benchmark 자료는 Git에 포함하지 않는다.
