# 고정 과제·조건 배정

계획 버전: `pilot-balanced-v3`. P01·P02·P03의 기존 계정과 비밀번호는 유지한다. 05·06·12번을 제외한 13개 과제를 각자가 모두 검수한다. 과제마다 세 사람에게 A/B/C를 하나씩 배정하고, 개인별 과제 순서는 순환시킨다. 참가자는 과제·조건을 직접 고르지 않는다.

| 계정 | 배정 순서 | A / B / C |
|---|---|---|
| P01 · 박주현 | 01A → 02B → 03C → 04A → 07B → 08C → 09A → 10B → 11C → 13A → 14B → 15C → 16A | 5 / 4 / 4 |
| P02 · 박지혜 | 07C → 08A → 09B → 10C → 11A → 13B → 14C → 15A → 16B → 01B → 02C → 03A → 04B | 4 / 5 / 4 |
| P03 · 신형림 | 11B → 13C → 14A → 15B → 16C → 01C → 02A → 03B → 04C → 07A → 08B → 09C → 10A | 4 / 4 / 5 |

화면 B의 내부 식별자는 B2다. 개인별 13회, 총 39회이며 A/B/C 각각 13회다. 각 사람은 같은 과제를 반복하지 않으며, 각 과제는 세 조건에서 한 번씩 검수된다. 원래 과제 번호를 유지한다. 세 명으로 모든 순서·이월 효과를 완전히 균형화한 본 실험은 아니며, 과제와 UI의 적합성을 찾기 위한 파일럿이다. 배정표·인포그래픽·제작 프롬프트는 output/team_pilot/에 보관한다.

06(행성·배송)은 행성 ID가 누락된 Input에서 Target의 대응을 판단하기 어렵다는 사용자 보고로 제외했다. 데이터나 정답을 임의로 보완하지 않는다. 05·12의 기존 제외도 유지하며, 원본 과제 파일과 기존 로그를 삭제하지 않는다. 남은 모든 과제는 조건별 초기 코드·Step·Input·Target을 공유한다. 추적 지원 여부는 과제의 의미적 타당성을 보장하지 않는다.

## 진행·재접속·로그

- ‘배정된 과제’에서 한국어 설명·Input·Target을 확인한 뒤 시작한다. Target은 검수 화면에서도 제공하며 자동 정오 판정은 표시하지 않는다. 과제 번호·조건·진행 순서는 읽기 전용이다. 초기 코드는 저장된 P0 코드를 실행하며 모델 재생성으로 정답을 고치지 않는다.
- 같은 배정에 대해 시작을 여러 번 눌러도 기존 세션을 반환한다. 계정별 서버 잠금으로 동시 시작 중복을 막는다. 새로고침/재로그인도 진행 중인 배정으로 복귀한다.
- 피드백을 제출하면 해당 시행을 완료한 것으로 취급한다. ‘다음 배정 과제로’에서 다음 Input을 확인한다. 중단/판단 어려움/과제 문제 보고도 완료에 포함하므로 정답 성공으로 해석하지 않는다. 약 10분간 이해·진행이 어렵다면 확정 없이 중단 피드백을 제출할 수 있다.
- 배정 목록은 완료·현재·잠금 카드를 표시한다. 완료 카드는 비활성화하며 다음 과제만 진행할 수 있다. 완료 표시는 정답 판정과 분리한다.
- assignment_id·plan_version을 세션과 이벤트에 기록한다. v1/v2 기록은 실제 과제 ID·조건이 v3와 일치할 때 진행률·세션을 유지한다. 제외된 06의 완료 여부를 다음 과제로 옮기지 않는다. 다른 조건의 과거 기록은 새 배정 완료로 세지 않는다. 이전 자유 점검 기록도 보존하며 전체 로그/CSV에서 구분한다.
- 관리자 ‘파일럿 로그’에서 배정 세션을 삭제하면 그 시행은 미완료가 된다. 해당 계정의 모든 배정 세션을 삭제하면 처음부터 다시 점검할 수 있다. 다른 계정·원본 과제·비밀번호는 유지한다.

## 한국어 과제 설명

16개 원본 영어 질문을 `scripts/localize_pilot_tasks.py`에서 한국어로 옮겼다. 원문은 description_original에 보관하며 코드·상수·테이블·Target·미계측 Step 제안은 바꾸지 않는다. 오류 해설을 요구사항에 섞거나 원문에 없는 정제 규칙을 추가하지 않는다. 과제 설명 자체가 불명확한 경우는 파일럿 피드백으로 따로 판단해야 한다.

## 실제 Python 실행과 lineage

native Python 실행과 별도로 pandas 표현을 출처 어댑터가 재실행한다. 어댑터의 DataFrame·Series·스칼라 결과가 실제 실행과 일치하는 경우에만 해당 출처를 채택한다. 직접 열 변경, 변수 재할당/별칭, Series 준비, 문자열 분리·추출, pandas 기본 groupby, 이름 지정 집계, groupby.size, Series 매핑, 제한된 DataFrame 생성자를 추가했다. 입력에서 유도된 행 수는 기여 행을 기록하며 임의의 원본 셀 값 출처를 만들지 않는다.

미지원 표현을 만나면 해당 변수/변경된 Frame을 미확인으로 처리하고 독립적으로 확인된 다른 데이터의 출처는 보존한다. 동일한 값이 나온다는 이유로 끊긴 lineage를 복원하지 않는다. 확인된 셀만 있는 partial과 전체 미확인 common을 구분한다. 선택/정렬/이름 변경 후에도 검증된 그룹 기여 문맥을 이어간다. A/B의 별도 코드/설명 배치는 유지하며, C의 셀 옆 ‘출처’ 버튼은 실제 원본 값과 확인된 참조만 표시한다. 별도의 데이터 경로 섹션은 다시 추가하지 않았다.

16개 원본 P0 출력은 유지한다. 05·12는 추적 지원 문제로 제외했고, 06은 과제 타당성 문제 보고로 추가 제외했다. 현재 참가자 공개 후보와 고정 배정은 13개다.

## 과제 타당성과 UI 피드백

질문지 `pilot-task-screening-v2`는 기존 3개 척도와 수행 상태를 유지하고, 과제 자체의 문제·약 10분간 정체로 중단한 상태를 추가한다. 설명 모호함, 입력 정보 부족, Target 근거·일관성 의심, UI 불편, 수정·실행 문제, 기타를 복수 선택할 수 있다. 자유 의견에는 문제의 표·열·값, 판단 근거, 막힌 Step과 불편을 기록한다. 이는 팀원의 자기 보고이며 시스템의 정오 판정이 아니다. 기존 피드백은 그대로 두고 JSON/CSV에 문제 유형을 함께 내보낸다.

검증: 웹 빌드, 배정 우회/중복/진행·로그 분리·접근 제한·선택 삭제 및 Python 실행/출처 관련 테스트. 16개는 격리 실행에서 저장 P0 출력과 비교하고 비어 있지 않은 원본 셀 참조가 실제 입력에 존재하는지 검사했다. 브라우저 및 새 LLM 호출은 수행하지 않았다.
