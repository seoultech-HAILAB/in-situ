# Workflow 검수 UI

현재 구현: 2026-10-30, presentation_version=natural-flow-v3.

## 탐색과 화면 배치

- A/B2/C는 전체 Step 순서·현재 위치·코드 참조·이전/다음 탐색을 공유한다. 방향키/Home/End도 사용할 수 있다. 순서 화살표와 코드 참조는 확인된 셀 계보를 뜻하지 않는다.
- A/C는 명시적으로 이동한 Step과 가까운 두 Step의 실제 표를 최대 3개 표시한다. 중간은 n−1/n/n+1, 양 끝은 가까운 세 개다. B2는 기존 단일 선택 Step의 코드+표 구성을 유지한다.
- 셀·행·열·표 내부 제목 선택과 Workflow 표시 범위를 분리했다. 검수 대상을 골라도 카드 범위가 자동 변경되거나 선택 카드가 확대되지 않는다. 화면 범위는 상단 탐색으로 직접 이동할 때 바뀐다.
- 표·카드·코드 영역은 내용에 따라 자연스럽게 늘어난다. 강제 높이·빈 예약 공간·자동 스크롤은 없다. 넓은 표/코드는 가로 스크롤을 사용한다. 별도 데이터 경로 섹션은 제거했고, 출처는 표 안에서 강조한다.
- 명시적 Step 전환의 가로 이동은 약 300ms, 입력/목표 및 검수 본문의 자연 높이 변화는 약 320ms다. 연속 변경은 진행 중 위치/높이에서 이어가며 완료 후 높이는 auto다. OS의 동작 줄이기 설정에서는 생략한다.
- 상단 페이지 제목·소개·진행 표시는 제거했다. 데모·연구자 내보내기·상태·설정은 Trace 헤더에 있다. 입력/Workflow/검토 구역과 선택 위치의 대비를 높였다.

## 제목·설명·코드

- 의미 있는 생성 Step 이름을 유지한다. 관찰 단계 2 같은 구문 관찰용 임시 이름은 실제 확인된 연산명으로 대체한다. 임의 Python의 의미를 새로 증명하거나 추정하지 않는다.
- C는 긴 summary/적용 인자 JSON/반복 조건 설명을 줄이고 짧은 연산 제목·조건·계산식·그룹 키를 해당 데이터에 표시한다. 추적 수준은 이름과 별도로 표시한다.
- A의 코드 탭은 같은 인접 범위를 따르고, B2는 선택 Step의 읽기 전용 코드를 제공한다. 둘 다 다크 Python 구문 강조와 1.5px 확대된 자연어 설명을 사용한다. 코드 원문은 바꾸거나 실행하지 않고 React 텍스트로 렌더링한다. 참가자 코드 편집은 없다.

## 실제 변화와 출처

현재 실행의 해당 Step 실제 입력→출력을 비교한다. Target이나 이전 실행, 화면상 바로 앞 Step을 대신 비교하지 않는다.

- 추가/삭제 열·dtype·크기 변화는 관찰한 표에서 계산한다. 이름 변경은 새 열/없어진 열로 표시하며 열 대응을 만들어내지 않는다.
- 확인된 행 ID 보존 어댑터는 공통 열의 변경 셀/행과 생존 행의 상대 순서를 표시한다. 필터로 번호가 당겨진 행을 모두 정렬 변화로 표시하지 않는다.
- 집계·조인·재구조화·공통 Python에서 개별 행 대응을 보장할 수 없으면 셀 변화나 행 추가/삭제를 추정하지 않는다. 실제 크기/스키마와 대응 미표시를 제공한다. 여러 입력의 크기/스키마 요약은 첫 실제 입력 기준임을 표시한다.
- 알려진 제외 행은 기본 펼침이며 접을 수 있다. 실제 입력 펼침·내부 연산 선택·확인된 기여 셀 강조를 유지한다. 확인되지 않은 출처를 복구하지 않는다.
- 같은 Step의 이전 실행 대비 비교는 별도 체크박스·코드/결과/경로 Δ·황색 밑줄이다. 현재 입력→출력 변화와 구분한다.

## 수정과 비교 조건

C의 작은 수정 버튼→자연어 댓글, A/B2의 패널 요청은 같은 범위·기준 버전 정책과 실행기를 사용한다. 범위 드래그와 실제 선택 데이터 검증, 전체 재실행·후속 결과/확인된 경로 갱신·되돌리기·최종 확정을 유지한다. 요청 실패는 마지막 성공 결과와 구분한다.

A/B2에 변환 셀 강조·제외 행·셀 출처·댓글 선택 기능을 추가하지 않았다. 코드 공개와 정보 배치 차이를 유지한다. 참가자 정오 판정·Target 불일치·의심 Step 추천은 없다. 동일 세션 조건 전환은 같은 실행의 표현 변경이며, 조건별 독립 실험 세션을 대신하지 않는다.

새 표현 버전과 수정 상호작용(selection-action-v2)을 기록한다. 이동은 step_selected, 폭 선택은 workflow_layout_changed, 제외 행 펼침은 removed_rows_expanded다. 과거 로그를 새 UI로 소급 해석하지 않는다.

## 검증과 제한

초기 Focus + Context 구현에서 Python 회귀 112개·실제 실행 fixture 기반 JS 9개·TypeScript/Vite 빌드가 통과했고, 1366×768의 2/3/6/8 Step 탐색과 데모 수정→후속 갱신→되돌리기→확정을 확인했다. 이후 사용자 요청으로 최종 UI 변경의 브라우저 검증/로컬 회귀 재실행은 생략했다. 최종 Vite 배포 파일 생성은 성공했으며, 과거 화면 기록을 최종 UI 검증으로 보고하지 않는다. 이번 UI 변경에서 실제 LLM API 추가 호출은 없다.

범용 행 추가 대응, 표 간 가로 스크롤 동기화, 행 자동 대응 정렬, 대형 표 가상화, 임의 분기 DAG 전체 그림은 미구현이다. 이전/다음은 실행 순서상 인접 Step이며 실제 입력/소비자와 다를 수 있다. 사람 파일럿과 최대 크기 표 성능은 별도 평가가 필요하다.

초기 관찰 계산 fixture 재현은 로컬 8000 서버에서 `.venv/Scripts/python.exe scripts/create-workflow-validation.py` 후 `node --test tests/table-changes.cjs`다. `.local/workflow-validation/`의 데이터는 합성 검증용이며 실제 Luna 출력/선정된 연구 과제가 아니다.
