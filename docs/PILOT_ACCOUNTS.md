# 개별 계정으로 팀 파일럿 진행하기

## 접속과 수행

팀 서버(로컬 `http://127.0.0.1:8001` 또는 기존 공유 HTTPS 주소)를 사용한다. 개발용 8000 서버는 로그인과 저장소가 별도이므로 개인별 로그 확인에는 사용하지 않는다.

관리자 PC에서 `./.venv/Scripts/python.exe scripts/provision_pilot_members.py`로 P01·P02·P03을 준비한다. 기존 계정·비밀번호·서명 키는 교체하지 않는다. 개인별 비밀번호는 `.local/pilot/팀원별_접속정보.txt`에 있으며 한 사람에게 한 계정을 전달한다. 관리자용 team은 기존 계정으로 유지한다. 계정의 실명 대응은 관리자가 별도로 정하며 서버에 실명을 요구하지 않는다.

1. 개인 ID로 로그인한다. 헤더의 ID를 확인한다. 한 브라우저에서 계정을 바꾸려면 로그아웃 후 다시 로그인한다.
2. [고정 배정표](PILOT_ASSIGNMENT.md)에 따른 현재 과제와 A/B/C를 확인하고 변환을 시작한다. 참가자는 선택하거나 건너뛰지 않는다. 같은 배정을 다시 시작하면 기존 세션으로 복귀한다.
3. 검수·자연어 수정·재실행·필요 시 되돌리기·최종 확정을 수행한다. 정오 판정이나 연구자 오류 해설은 보이지 않는다.
4. 끝났거나 중단한 경우 화면 아래 ‘피드백 남기기’를 누른다. 최종 확정 없이도 피드백을 남길 수 있다. 제출 후 ‘다음 배정 과제로’를 눌러 계속한다.

개별 계정은 고정된 파일럿 배정을 수행하며 연구자 코드·오류 해설·진단·전체 로그와 다른 사람의 세션에 접근하지 못한다. 각 배정은 하나의 시행이며 재접속으로 중복 시행을 만들지 않는다. 임의 인원에 대한 정식 실험 무작위 배정은 구현하지 않았다.

## 수집 내용

- 서버 로그인에서 확인한 participant_id, 실제 작업자 actor_id, 과제 ID/번호, 조건, 세션 ID.
- 선택/탐색, 자연어 수정 요청과 범위, 실제 코드·실행 버전, 성공·실패, 되돌리기, 최종 확정.
- 문항 버전 `pilot-short-v1`: 과제 명확성·단계 탐색·데이터 변화 이해의 1~5 평가(해당 없음 가능), 스스로 판단한 수행 상태, 선택적 메모.
- 피드백은 제출 당시 실행 버전/조건/상태에 연결한다. 같은 제출 번호 재전송은 중복 저장하지 않으며 버전이 달라진 응답은 거절한다. 여러 피드백은 삭제 없이 누적된다.

문항은 파일럿용 자체 질문이며 표준화된 사용성 척도가 아니다. 수행 상태는 자기 보고로 보관하며 정답 판정으로 해석하지 않는다. 이벤트 시각은 서버 UTC 기준이며 화면에는 브라우저 지역 시각으로 표시한다. 대기·이탈 시간을 제외한 능동 작업 시간은 계측하지 않는다. 기존 review_ms는 해당 실행의 검수 시작 이후 경과 시간이다.

기존 공용 계정의 기록은 개인에게 소급 배정하지 않는다. 새 인증 참가자는 자신이 생성한 세션만 볼 수 있으며 예전 소유자 없는 세션은 관리자에게만 남는다. 관리자가 개인 세션에 개입하면 실제 작업자도 로그에 남고 요약의 mixed_actors가 표시된다.

## 관리자 내보내기와 검증 기록 삭제

동일한 팀 서버에 기존 **team** 관리자 계정으로 로그인한 후 **개발자 옵션 → 파일럿 로그**를 연다.

- ID 필터와 시행 목록으로 개인별 진행을 확인한다. ‘과제 요약 CSV’, ‘피드백 CSV’, ‘상세 로그 JSONL’을 내려받을 수 있다. 요약 CSV는 세션당 한 행이며 최신 피드백과 그 실행 버전을 표시한다. 전체 응답 이력은 피드백 CSV에 있다.
- 본인이 먼저 P01 등으로 점검해도 된다. 점검 후 관리자 화면에서 해당 세션만 체크하고 **선택한 테스트 로그 삭제**를 누른다.
- 삭제는 해당 세션 JSON(실행 이력·이벤트·피드백 포함)을 `.local/pilot/deleted_sessions/<batch-id>/`로 이동한다. 이후 진행 기록·내보내기·세션 조회에서 제외된다. 과제 파일·Input·P0 코드·계정·비밀번호·다른 사람의 세션은 유지한다.
- 목록을 가져온 뒤 새 활동이 생긴 세션은 409로 삭제를 거절한다. 새로고침 후 다시 선택해야 한다. 복구하려면 서버를 멈춘 뒤 보관한 `<session-id>.json`을 원래 sessions 폴더로 이동한다. 삭제 목록과 작업자는 보관 폴더 manifest.json에 남는다.
- 기존 익명/공용 기록은 이 삭제 메뉴의 대상이 아니다. 여기서는 이미 수집한 기록을 자동으로 지우지 않았다.

로그·접속 정보·백업은 `.local/`에 보관하며 Git에 포함하지 않는다. 이 변경은 웹 빌드와 계정/로그/피드백/선택 삭제 API 테스트로 확인했다. 브라우저 화면과 실제 모델 호출은 추가 검증하지 않았다.
